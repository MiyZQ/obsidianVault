
### 1.理论

请看一下代码：

```c
int i;
for(i=1;i<=n-2;i+=3) {
    sum+=a[i];
    sum+=a[i+1];
    sum+=a[i+2];
}
for(;i<=n;++i)sum+=a[i];
```

和

```cpp
for(int i = 1; i <= n; ++i)sum += a[i];
```

那个快？（不开 O 2）你可能会说第二个，第一个又是 `+3` 又多一个循环的。

然而，是第一个快。

为何？

原因在于第一份代码会刺激 CPU 的并发计算，会使三个语句几乎同时运行，在 n 较大时会有优势。

同时运行？不是说好了 CPU 只能做一件事吗？

其实不是，CPU 里有许多个功能单元，不同功能单元能同时工作。CPU 也有很多核，每个核一般可以同时开多个线程。而且还有显卡，FPU 之类的。

所以，你可以写第二个代码。

这里，我想引用一下大佬的说法。

我们把第一个代码称为 **(3,1) 循环展开**，

而以下代码：

```cpp
int i, sum0, sum1, sum;
for(i = 1; i <= n - 1; i += 2) {
    sum0 = sum0 + a[i];
    sum1 = sum1 + a[i + 1];
}
for(i; i <= n; ++i)sum0 += a[i];
sum = sum0 + sum1;
```

称为 **(2,2) 循环展开**。

对比 (3,1) 循环展开，我们发现 (2,2) 循坏展开 用了两个变量 sum 0、sum 1 来累积和，这就是 (2,2) 中的后面的 2 的含义。

一个结论：(2,1) 的速度要低于 (2,2) 的速度。

为什么？

这里，我们要引入一个概念，叫 **数据相关性** 。字面意思，数据相关度的大小。

(2,2) 的是用 sum 1 和 sum 2 两个东西接受数组 a，相关性低。

而 (2,1) 用一个变量接受 a 数组的，并行时相关性高，运行速度低。

那么哪个最快呢？这依赖程序和电脑 CPU 等的具体情况。

### 2.用法

循环展开好是好，这可读性太低了。这也正是循环展开的劣势。

怎么办？编译器+O 2！

但是，编译器不一定认为你需要循环展开。

比如你一次循环有 20 次操作，展开之后一次好几十次操作，显然编译器不会认为这需要，当然这确实不需要。

但，如果你有两三四五个操作，好多时候编译器都不认为你需要展开，但这展开还是要快一点。

所以第一点，把每句占成一个循环。

否则：

> 你影响它的循环展开了。 ——NOI 冬令营《并发计算》

第二点是，你写的时候尽可能降低数据的相关性。

例如：

```cpp
for(int i=1;i<=n;++i)
    for(int j=i+1;j<=n;++j)a[i]+=b[i];
```

和

```cpp
for(int i=2;i<=n;++i)
    for(int j=1;j<i;++j)a[j]+=b[j];
```

第二个 数据相关性 明显较低，更容易刺激并发运算。

虽然例子略显低等，但意思达到即可。

当然，有相当少的毒瘤题目会迫使你手动循环展开（因为 O 2 不会“展的很开”，效率可能达不到极限）。

这时，建议使用 (8,8)/(7,7) 循环展开，主要是现在的评测机器核数相当多。

同时，不要用 `while` 代替 `if`，这会阻碍并发运算。

### 3.关于指令集：

循环展开是激发并发运算，而指令集是强行并发。当我们的程序几乎没有数据相关性时，可以使用。

虽然这是一种在现代计算机中极为强悍的常数优化。**但是，使用这个，属于“破坏竞赛公平性”，在 OI 中使用可以得到零分的好成绩。**

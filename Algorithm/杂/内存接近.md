
### 1.理论

什么叫内存接近呢？

请看一下两行代码：

```cpp
++num[1],++num[100001]
```

和

```cpp
++num[1],++num[2]
```

这两行代码看似都是两次自增命令，实际执行时间是有些不同的。

这是因为，假设不考虑并行，第一行代码调用时指针需要从 num+1 走到 num+100001 才能执行下一步。而第二行从 num+1 走“一步”即可。

你可能觉得这没有什么，内存里“跑”的很快。但如果这是非常多次执行呢？或者“跑“得非常远，跑遍了整个内存呢？这对于卡常绝对有意义，甚至会使 AC 退化为 TLE。

由此，在卡常时，我们要注意内存接近。

对了，说到二维数组，很多人说

```cpp
for(int i=1;i<=n;++i){
    if(i&1)
        for(int j=1;j<=n;++j){}
    else 
        for(int j=n;j>=1;--j){}
}
```

比

```cpp
for(int i=1;i<=n;++i){
    for(int j=1;j<=n;++j){}
}
```

要快。

其实不是。二维数组的存储方式是 `[0][0],[0][1].....[1][0].......` 的。所以抛开判断都是第二种快。所以就正常写就行。

另一种比较常用的优化是数组顺序。

### 2.常见例子

矩阵乘法中这样的写法：

```cpp
for(int i=1;i<=n;++i)
    for(int k=1;k<=n;++k)
        for(int j=1;j<=n;++j)
            p[i][j]+=a[i][k]*b[k][j];
```

比

```cpp
for(int i=1;i<=n;++i)
    for(int j=1;j<=n;++j)
        for(int k=1;k<=n;++k)
            p[i][j]+=a[i][k]*b[k][j];
```

快得多。

ST 表中 `f[i][j]` 表示 i 为起点，就比表示 j 为起点慢，原因显然。

此外，还有减小大数组占用空间，这样避免访问大数组内外变量指针的“奔袭”。这也是滚动数组往往比较快的原因。

还有，大量的遍历图（比如点分治）时用 `vector` 存图要比链式前向星要快。

至于为什么说是“大量”，因为动态数组申请空间慢，实在想要内存连续性参考[优化 vector 效率](卡常相关.md#优化%20vector%20效率)

## 快读快写

主要用于解决 IO 数据量超大的情况
速度上：
cin、cout < scanf、printf = 关闭同步流写法 <  解绑写法 < getchar < fread
#### 关闭同步流写法

```cpp
ios::sync_with_stdio(false);
int a;
cin>>a;
cout<<a;
```

> [!NOTE]
> 关闭同步流后避免使用 `endl`，改用 `'\n'`
> cin、cout 不能和 scanf、printf、fread、getchar 等混用

#### getchar 写法

```cpp
inline int read() {
	int x{0},f{1};char ch=getchar();
	for(;(ch>='0'&&ch<='9')||ch=='-';ch=getchar())
		ch=='-'?f=-1:x=x*10+ch-'0';
	return x*f;
}

inline void write(int x) {
	if(x<0){putchar('-');x=-x;}
	if(x>9) write(x/10);
	putchar(x%10+'0');
}
```

#### 解绑写法

```cpp
ios::sync_with_stdio(false);
cin.tie(0);
```

> [!NOTE]
> cin、cout 使用前会强制刷新输出，使用 tie 解绑解除这个效果

#### fread 写法

只是修改上面 getchar 写法为 gc 函数
```cpp
#include<cstdio>
char buf[1<<21],*p1=buf,*p2=buf;
#define gc()  (p1==p2 && (p2=(p1=buf)+fread(buf,1,1<<21,stdin),p1==p2)?EOF:*p1++)

inline int read() {
	int x{0},f{1};char ch=gc();
	for(;(ch>='0'&&ch<='9')||ch=='-';ch=gc())
		ch=='-'?f=-1:x=x*10+ch-'0';
	return x*f;
}
```

#### 配套 fwrite 快写

```cpp
#include<cstdio>
char obuf[1<<21];int op=0;
#define pc(ch) (op==(1<<21)?fwrite(obuf,1,op,stdout),op=0:0,obuf[op++]=(ch))

inline void write(int x) {
	if(x<0) {pc('-');x=-x;}
	if(x>9) write(x/10);
	pc(x%10+'0');
}

inline void flush() { if(op) {fwrite(obuf,1,op,stdout);op=0;} }
```

> [!NOTE]
> 使用 fwrite 快写必须在写后使用 flush 清空缓冲区

## if-else 与 switch-else

switch-else 基本比 if-else 更快，这种差异在分支多时会放大

分支很少时，编译器会考虑编译成 if-else；分支多时，若 case 值紧密，会用类似基数排序的方式记录 case，速度 O(1)，若 case 稀疏，会采用二分法

## 巴雷特约减

用于取模的数很大时，巴雷特约减优化除法，具体说，令 $I=\large\frac{n}{mod}$ 接近一个整数，则只要算 $\large\frac{x\times I}{n}$ 即可

考虑直接给 $I$ 下取整，设 $x$ 最大为 $N$，$m$ 为 $mod$，要求
$$
\lfloor \frac{x}{m} \rfloor - \frac{Ix}{n} \leq 1
$$
由下取整性质 $I \leq \large \frac{n-m+1}{m}$，代入左式继续放缩为
$$
LHS \geq -\left\{\frac{x}{m}\right\}+\frac{x}{n}
$$
由 $\large \left\{\frac{x}{m}\right\} \leq \frac{m-1}{m}$ 化简即要求
$$
n \geq \frac{mN}{2m-1}
$$
取 `1ll<<62` 即可

```cpp
class Bart {
public:
	int I,m;
	Bart(int mod) m{mod},I{(1ll<<62)/mod} {}
	int operator()(int x){
		int tp=x-((__int128)x*I>>62)*m;
		while(tp>=m)tp-=m;
		return tp;
	}
};
int main() {
	Bart getmod(998244353);
	cout<<getmod(1145141919*114514)<<'\n';
}
```

## 优化 vector 效率

#### 减少申请空间次数

在大量加入元素前，统计需要的个数，进行 `reserve` 操作
减少不必要的 `clear` 后重新申请内存，而是直接更改，或用 `pop_back` 释放较少空间

#### 将 push_back 换用 emplace_back

区别在于，`e_b` 在申请的新空间直接构造，`p_b` 先对元素复制，将放入 vector，前者效率高一点

## 关于 unordered_map

按理说，`unordered_map` 要比 `map` 快，因为少了一个 `log` 。然而 `unordered_map` 有极为巨大的常数。

虽然 `map` 的常数也不小，但是开 O 2 后会优化不少，然而 `u_map` 不行，而且 `u_map` 也存在一些方式可以卡掉（CF 就经常这么干）。

所以有一些时候 `map` 会比 `unordered_map` 快。

这样一来，`u_map` 本身一个  的数据结构就相当于退化成了 `log n` 的复杂度（有时更甚），直接导致“复杂度”退化。这已经不完全算常数的范畴了。

所以，这东西能不用尽量别用。尽量用 `hash_policy` 里面的。要用，也别塞结构体，既难写，又常数巨大。

## 一些常数看起来不大但是其实不然的 STL

1. `lower_bound` 的常数比较大，甚至比 `map` 快不了多少，卡常可以手写二分。
2. `deque` 和衍生的 `queue` 和 `stack` 常数不小（虽然比 vector 的 push_back 快），还有及其抽象的超大基底空间常数，建议不用。
3. `sort` 一般常数不大，但是对几乎排好序的数常数不小。

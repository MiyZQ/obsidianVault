#虚拟环境
还可见[拾遗-虚拟环境](../../../AInote/计算机拾遗/第六讲_代码打包与发布.md#2.%20虚拟环境)
## 用途

虚拟环境用于为每个项目单独隔离一套独立的依赖包，互不干扰
- 控制不同的包版本
- 让项目依赖干净独立
- 方便复制、移植项目
- 不污染系统 python
- 多版本 python 共存

常用的虚拟环境工具包括 venv、conda、pipenv 等

## 组成

包含 python 解释器、激活脚本、第三方包

- python 解释器：运行代码
- 激活脚本：激活虚拟环境的 key
- 第三方包：包含使用的各种工具

使用 python 内置 venv 创建虚拟环境
`python -m venv myvenv`

- python 解释器位置 `myvenv/bin/python`
- 激活脚本位置 `myvenv/bin/activate`
- 第三方包位置 `myvenv/lib/site-packages`

## 依赖管理

一般使用 requirements.txt 记录和复现项目环境，可用：
```bash
(.venv) pip freeze > requirements.txt
```

从 requirements 文件中安装依赖：
```bash
(.venv) pip install -r requirements.txt
```

> [!Attention]
> 如果需要删除虚拟环境，在删除前执行：
> ```bash
> deactivate
> ```
> 退出环境，否则当前 Shell 会保留失效的环境变量
> 
> 另外如果项目有 git 管理，应将 .venv/ 加入 .gitignore，只提交 requirements.txt，虚拟环境体积大且路径绑定，不应纳入版本控制
> ```git
> # .gitignore 推荐配置
> .venv/
> __pycache__/
> *.pyc
> .env
> *.egg-info/
> ```

## 实例

```bash
# 1. 创建并进入项目目录
mkdir my_site && cd my_site

# 2. 创建虚拟环境并激活
python3 -m venv .venv
source .venv/bin/activate    # Windows: .venv\Scripts\activate

# 3. 安装 Django 并记录依赖
(.venv) pip install django==4.2
(.venv) pip freeze > requirements.txt

# 4. 初始化 Django 项目
(.venv) django-admin startproject config .

# 5. 数据库迁移并启动开发服务器
(.venv) python manage.py migrate
(.venv) python manage.py runserver

# 6. 开发完成，退出环境
(.venv) deactivate
```

## 其他命令
#### 指定 Python 版本
```python
python3.8 -m venv .venv  # 使用 Python 3.8
```
#### 创建不带 pip 的环境
```python
python -m venv --without-pip .venv
```
#### 创建继承系统包的虚拟环境
```python
python -m venv --system-site-packages .venv
```

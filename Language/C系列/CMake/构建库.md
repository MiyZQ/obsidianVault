> 构建库的主要目的是避免暴露源码、避免每次编译全部重编等等

库文件分为两种：
- 静态库 `libxxx.a` (Linux)、`.lib` (Windows)：
	编译链接时嵌入程序，生成单个 .exe 文件
- 动态库 `.so` (Linux)、`.dll` (Windows)：
	编译仅记录依赖，运行加载，生成 .exe 文件和相应库文件夹

CMake 中关键字：静态库用 `STATIC`，动态库用 `SHARED`

---

### 构建静态库示例

目录结构如
```plaintext
main.c
CMakeLists.txt
Lib/
	demo.h
	demo.c
```

#### 顶部 CMake 直接创建库
适合简单项目：
```cmake
cmake_minimum_required(VERSION 3.20)
project(demo C)

add_library(Lib STATIC
	Lib/demo.c
)

target_include_directories(Lib PUBLIC Lib)
add_executable(${PROJECT_NAME} main.c)
target_link_libraries(${PROJECT_NAME} PRIVATE
	Lib
)
```

#### 分目录
适合大型项目有复杂分类：
```cmake
# 顶层CMakeLists
cmake_minimum_required(VERSION 3.20)
project(demo C)

add_subdirectory(Lib)

add_executable(${PROJECT_NAME} main.c)
target_link_libraries(${PROJECT_NAME} PRIVATE
	Lib
)

# Lib中的CMakeLists
add_library(Lib STATIC demo.c)
target_include_directories(Lib PUBLIC
{CMAKE_CURRENT_SOURCE_DIR})
```

正常构建工程后，Build 文件夹中产出 `.lib` 或 `.a` 文件，*如果从外部导入第三方库，需要这个库文件和对应的头文件*，CMake 写法为：
```cmake
# lib存放.a文件
link_directories(${CMAKE_SOURCE_DIR}/lib)
# inc存放.h文件
target_include_directories(${PROJECT_NAME} PRIVATE
${CMAKE_SOURCE_DIR}/inc)
# 写库名
target_link_libraries(${PROJECT_NAME} PRIVATE Lib)
```

## 1. 项目初始化与启动

### 基本流程

```bash
# 1. 创建项目文件夹
mkdir project-name

# 2. 进入文件夹后，打开命令面板（CMV）
CMV

# 3. 输入 cloud 启动 Claude Code
cloud

# 4. 选择"相信此文件夹"(Trust Folder)

# 5. 在输入框描述需求
输入：帮我制作一个摄影师个人网站
```

### 工作流程

Claude Code 启动后会经历以下阶段：

1. **计划模式** - 分析需求，输出执行计划
2. **权限申请** - 申请使用工具的权限
3. **自动执行** - 按计划完成任务
4. **结果展示** - 自动打开生成的文件

## 2. 计划模式

### 计划模式选项说明

| 选项 | 说明 |
|------|------|
| **批准并自动同意** | 同意计划，且后续所有编辑工具使用无需再确认 |
| **批准但需手动同意** | 同意计划，但后续每次编辑工具使用需手动确认 |
| **讨论** | 暂停执行，与 Claude Code 讨论计划的改进建议 |

### 计划模式的特点

- Claude Code 会输出一份详细的执行计划
- 在计划模式中，可以与 Claude Code 进行多轮讨论
- Claude Code 会询问项目细节，以便更准确地理解需求

## 3. 权限管理

### 权限申请选项

| 选项 | 说明 |
|------|------|
| **同意这次** | 仅本次同意，下次使用仍需申请 |
| **同意并记住** | 在当前会话中，以后都自动同意该命令 |

### 权限类型

- **工具权限**：如 `Read`、`Edit`、`Bash` 等
- **命令权限**：如 `start`、`WebFetch` 等
- **危险命令权限**：如 `Write`、`Delete` 等高风险操作

## 4. 回滚功能

### 使用场景

当生成的结果不符合预期，且修改后越来越乱时使用。

### 操作方法

```bash
# 方法1：使用命令
/rollback

# 方法2：使用快捷键
双击 Esc 键进入回滚页面

# 方法3：使用方向键
向下键切换节点
```

### 回滚选项

| 选项 | 说明 |
|------|------|
| **回滚代码和对话** | 恢复到该节点，代码和对话历史都回滚 |
| **仅回滚对话** | 只回滚对话，代码保持不变 |
| **仅回滚代码** | 只回滚代码，对话保持不变 |
| **压缩为摘要** | 将该节点之前的内容压缩成摘要保存 |
| **取消** | 取消回滚操作 |

### 重要限制

> ⚠️ **注意**：Claude Code 的回滚功能只能回滚使用**内置工具**创建的文件和文件夹。如果使用命令（如 `Bash` 命令）创建的文件，**无法回滚**。

## 5. 模式切换

### 快捷键

```bash
Shift + Tab
```

### 可切换的模式

| 模式 | 说明 |
|------|------|
| **计划模式** | Claude Code 先讨论需求，输出详细计划后再执行 |
| **自动同意编辑工具** | 直接执行，编辑工具自动同意 |

### 项目细节询问

在计划模式中，Claude Code 会询问项目细节：
- 使用 **上下左右键** 切换选项
- 使用 **回车键** 确定选择

## 7. 思考强度调节

### 命令

```bash
/maximize-depth
# 或使用 /config 命令（在选项列表中找到思考强度调节项）
```

### 可选强度等级

| 等级 | 说明 | 适用场景 |
|------|------|----------|
| `min` | 最小思考深度 | 简单任务 |
| `low` | 低思考深度 | 基础任务 |
| `medium` | 中等思考深度 | 一般任务 |
| `high` | 高思考深度 | 复杂任务 |
| `very high` | 很高思考深度 | 复杂项目 |
| `max` | 最大思考深度 | 大型重构、复杂架构 |

### 使用方法

```bash
/maximize-depth max
# 执行后右下角会显示 SAT 变成 max
```

> 💡 **适用场景**：适合大型工程、需要深度思考的重构任务。

## 9. 自动同意权限

### 命令

```bash
/anti-consent
```

### 效果

启动 Claude Code 后会自动同意**所有**权限申请。

### ⚠️ 安全警告

> ⚠️ **危险操作**：该命令会自动同意所有权限，包括高风险操作。**强烈建议不要在生产机上使用**，仅限安全的测试环境。

## 11. 上下文管理

### 查看上下文使用情况

```bash
/context
```

### 显示信息

- 当前上下文占用百分比（如 13%）
- 各种提示词的占比
- Token 使用明细

### 上下文压缩

```bash
# 压缩上下文（释放空间，保留核心信息）
/compact
```

### 上下文重置

```bash
# 完全清空上下文
/clear
```

### 说明

- 上下文过满可能导致模型效果下降
- 清空后 Claude Code 仍对项目有基础了解（因为 `CLAUDE.md` 文件起作用）

## 12. Skills 系统

### 概念理解

Skills 可以理解为**一份说明书**。当 Claude Code 需要执行任务时，可以根据说明书的名字选择需要的技能。

### 目录结构

```
用户目录/
└── skills/          # 全局 skills 目录
    └── [skill-name]/
        └── skill.md # Skill 定义文件
```

### 访问用户目录

1. 在地址栏输入 `~` 打开用户目录
2. 进入 `skills` 文件夹

### 查看已安装的 Skills

```bash
/skills
```

### 创建新 Skill

1. 在 skills 目录下新建文件夹（命名即为 skill 名称）
2. 启动 Claude Code
3. 输入创建指令，让 Claude Code 生成 skill.md 文件

### Skill 文件格式

```markdown
---
name: skill-name           # Skill 名称
description: 描述说明      # Skill 用途描述
---

# 完整指令
你的 Skill 要执行的具体指令内容...
```

### 示例

创建"美食报告" Skill：

```markdown
---
name: meal-report
description: 生成精美的美食报告
---

生成一份美食报告，包括：
- 菜品名称
- 食材列表
- 制作步骤
- 配图建议
```

## 13. Agents 系统

### 与 Skills 的区别

| 特性 | Skills | Agents |
|------|--------|--------|
| 执行方式 | 在主对话中执行 | 独立于主对话的技能体 |
| 上下文 | 共享主会话上下文 | 独立上下文，不污染主会话 |
| 用途 | 复用提示词模板 | 处理特定业务，结果返回主会话 |

### 启动 Agents 功能

```bash
/agent
```

### Agent 选项

| 选项 | 说明 |
|------|------|
| **正在运行的 agent** | 查看和管理当前运行的 agent |
| **Create** | 创建新的 agent |

### Agent 级别

| 级别 | 说明 |
|------|------|
| **项目级** | 只在当前项目生效，其他项目不可见 |
| **用户级** | 在任何项目都可以使用 |

### 创建 Agent 流程

```
1. 选择 Create 生成新的 agent
2. 选择级别（项目级/用户级）
3. 选择生成方式：
   - 让 Claude Code 自动生成
   - 手动配置
4. 描述需要的 agent 功能
5. 配置工具权限
6. 选择驱动模型
7. 选择颜色标识
8. 配置记忆文件存储位置
9. 预览和保存
```

### 工具权限配置

```
All Tools → 取消所有工具权限 → Read Only（只读） → Continue
```

### 记忆文件存储位置

| 选项 | 说明 |
|------|------|
| **项目级别（Git 同步）** | 提交到 Git 后，别人拉取也能同步记忆 |
| **不保留记忆** | 每次都是全新会话 |
| **用户级别（云端）** | 所有项目可读取 |
| **用户级别（本地）** | 保存在本地，Git 提交不会上传 |

### 调用 Agent

```bash
# 在主对话中调用 agent
使用代码审核 agent 帮我检查代码
```

## 14. 插件功能

### 概念理解

插件是集成了 **Skills + Agent + MCP + Hooks** 的整合包。

### 启动插件市场

```bash
/plugin
```

### 安装位置选项

| 选项 | 说明 |
|------|------|
| **用户目录** | 其他项目也能使用 |
| **项目目录** | 当前项目和拉取该项目的用户可用 |
| **本地项目目录** | 仅当前电脑、当前项目可用 |

### 使用示例：Front End Design 插件

1. 在 `Discover` 页面选择 `Front End Design` 插件
2. 选择安装位置（示例选择"当前项目"）
3. 安装完成后，Claude Code 会使用该插件能力

### 使用效果

使用插件后，生成的效果明显优于不使用插件，可以减少后续微调工作量。

## 1. 开发环境概述

### 1.1 两种开发环境类型

| 类型 | 特点 | 适用场景 |
|------|------|----------|
| **终端环境 (Terminal-based)** | 使用 TMUX 分屏，同时运行 Vim + Shell + Docker | 远程登录服务器、无法安装复杂软件时 |
| **图形化 IDE (Graphical IDE)** | VS Code 等集成所有功能（文本编辑、代码补全、自动格式化等） | 需要 AI 功能深度集成、快速上手 |

> **IDE** = Integrated Development Environment（集成开发环境），即将所有开发工具集成在一个应用中。

### 1.2 Vim 的普适性

Vim 的设计理念已被广泛应用于多种工具：
- VS Code 支持 Vim 模式
- Shell（Zsh/Bash）支持 Vim 键位绑定
- 许多云端开发环境支持 Vim 模式

**核心学习目标**：掌握 Vim 的核心操作思想，这些概念可迁移到各种支持 Vim 模式的编辑器中。

## 2. Vim 文本编辑器

### 2.1 核心设计思想

Vim 的核心理念：**将文本编辑界面视为一种编程语言**，通过组合不同的"原语"（primitives）来高效操作文本。

**关键洞察**：在键盘和鼠标之间切换是缓慢的。如果能始终保持手指在键盘上，并拥有高效的操作界面，编辑速度将大幅提升。

### 2.2 Vim 模式系统

Vim 是**模态编辑器 (Modal Editor)**，不同的模式用于执行不同类型的操作：

| 模式 | 进入方式 | 用途 |
|------|----------|------|
| **Normal Mode**（普通模式） | 默认模式，按 `Esc` 进入 | 移动光标、选择文本、执行编辑命令 |
| **Insert Mode**（插入模式） | 按 `i` 从 Normal 进入 | 像普通编辑器一样直接输入文本 |
| **Visual Mode**（可视化模式） | 按 `v` | 选择字符 |
| **Visual Line Mode** | 按 `Shift+V`（大写 V） | 选择整行 |
| **Visual Block Mode** | 按 `Ctrl+V` | 选择矩形文本块 |
| **Command Mode**（命令模式） | 按 `:` | 执行保存、退出等命令 |
| **Replace Mode** | 按 `Shift+R`（大写 R） | 替换现有文本 |

### 2.3 移动命令 (Movement)

#### 基本移动

| 命令 | 功能 | 记忆方法 |
|------|------|----------|
| `h` / `←` | 光标左移 | - |
| `j` / `↓` | 光标下移 | - |
| `k` / `↑` | 光标上移 | - |
| `l` / `→` | 光标右移 | - |
| `w` | 移动到下一个单词开头 | Word |
| `b` | 移动到当前单词开头 | Beginning/Back |
| `e` | 移动到当前单词结尾 | End |

> **效率提示**：使用 `hjkl` 而非方向键可以保持手指在主行（home row），节省移动时间。

#### 行内与屏幕定位

| 命令 | 功能 |
|------|------|
| `0` | 跳转到行首 |
| `$` | 跳转到行尾 |
| `^` | 跳转到行首（非空白字符） |
| `gg` | 跳转到文件第一行 |
| `G` | 跳转到文件最后一行 |
| `H` | 跳转到屏幕顶部 | 
| `M` | 跳转到屏幕中部 |
| `L` | 跳转到屏幕底部 |
| `:n` | 跳转到第 n 行（如 `:123`） |

#### 滚动与跳转

| 命令 | 功能 |
|------|------|
| `Ctrl+D` | 向下滚动半屏 |
| `Ctrl+U` | 向上滚动半屏 |
| `%` | 跳转到匹配的括号（`(`/`[`/`{`） |
| `f<char>` | 跳转到当前行下一个指定字符处 |
| `t<char>` | 跳转到指定字符前一个位置 |
| `/<pattern>` | 搜索文本，按 `n` 跳到下一个匹配 |

### 2.4 选择命令 (Selection)

通过可视化模式选择文本后，可以配合移动命令扩大选区：

```vim
v + 移动命令   " 字符选择模式
V + j/k       " 行选择模式
Ctrl+V + j/k  " 块选择模式（矩形选区）
```

### 2.5 编辑命令 (Edit)

| 命令 | 功能 |
|------|------|
| `i` | 进入插入模式（在当前字符前插入） |
| `a` | 进入插入模式（在当前字符后追加） |
| `o` | 在当前行下方新建一行并进入插入模式 |
| `O` | 在当前行上方新建一行并进入插入模式 |
| `x` | 删除当前字符 |
| `dd` | 删除整行 |
| `d<motion>` | 删除指定范围（如 `dw` 删除一个词） |
| `yy` | 复制整行 |
| `y<motion>` | 复制指定范围 |
| `p` | 粘贴 |
| `u` | 撤销 (Undo) |
| `Ctrl+R` | 重做 (Redo) |
| `c<motion>` | 删除指定范围并进入插入模式 |

### 2.6 组合与计数 (Counts)

Vim 的强大之处在于可以组合命令和计数：

```
<count><action><motion>
```

**示例：**
- `5j` — 向下移动 5 行
- `3w` — 向前移动 3 个单词
- `5u` — 撤销 5 次操作
- `10dd` — 删除 10 行

### 2.7 修饰符 (Modifiers)

| 修饰符 | 含义 | 示例 |
|--------|------|------|
| `i` | Inside（内部） | `ci"` 删除引号内的内容 |
| `a` | Around（周围） | `ca(` 删除包含括号的内容 |

### 2.8 实际演示：修复 FizzBuzz 程序

使用 Vim 高效修复一个有 bug 的 Python FizzBuzz 程序：

1. **添加 main 函数调用**：按 `G` 跳到文件末尾 → 按 `o` 新建行 → 输入代码 → 按 `Esc` 返回普通模式
2. **修复 range 起始值**：按 `/range` 搜索 → 定位到目标位置 → `i` 进入插入模式 → 添加 `1,` → `Esc` 返回
3. **修改字符串**：按 `:6` 跳到第 6 行 → `ci"` 删除引号内内容 → 输入新内容 → `Esc` 返回
4. **保存退出**：`:wq`

**关键模式**：大部分时间处于普通模式，需要编辑时进入插入模式，完成后立即返回。

### 2.9 如何掌握 Vim

1. **通过教程学习**：Vim 自带教程（`vimtutor`），建议花时间练习基础命令
2. **强制使用一个月**：将所有软件切换到 Vim 模式，强迫自己适应
3. **主动搜索更好的方法**：如果发现某个操作很繁琐，一定存在更高效的方式，搜索或询问 AI 即可找到解决方案

> **编程原则**：最优秀的程序员往往是"懒惰"的人——如果某个操作需要大量重复输入，一定有更优解。

## 3. 语言服务器与代码智能

### 3.1 Language Server Protocol (LSP)

**语言服务器协议**是一种标准化的通信协议，用于 IDE 与语言特定功能之间的通信。

**架构优势**：将 M×N 的问题（每种 IDE 需要为每种语言单独适配）简化为 M+N（只需为每种 IDE 和每种语言分别实现一次）。

```
IDE (实现 LSP 客户端) ←→ LSP ←→ 语言服务器 (实现 LSP 服务器)
```

### 3.2 语言服务器提供的能力

| 功能 | 说明 |
|------|------|
| **代码补全 (Code Completion)** | 输入 `.` 后显示对象的所有可用方法和字段 |
| **内联文档 (Inline Documentation)** | 显示类型定义、文档字符串等信息 |
| **跳转到定义 (Go to Definition)** | 右键点击符号，跳转到其定义位置 |
| **查找引用 (Find References)** | 查找某个符号在整个代码库中被使用的地方 |
| **自动导入 (Auto Import)** | 自动检测未导入的模块并添加 import 语句 |
| **实时错误检查** | 输入时即可看到类型错误、未定义方法等提示 |

### 3.3 配置建议

在 VS Code 等 IDE 中，为使用的编程语言安装对应的语言服务器扩展。例如搜索"Python support VS Code"或"Go support VS Code"即可找到相关插件。

## 4. AI 辅助编程

### 4.1 主要工具类型

| 类型 | 特点 | 适用场景 |
|------|------|----------|
| **代码自动补全 (Autocomplete)** | 在光标位置后补全代码 | 快速编写简单函数、常规模板代码 |
| **内联聊天 (Inline Chat)** | 选中代码后向 AI 发出指令 | 修改现有代码、重构 |
| **编码代理 (Coding Agents)** | 对话式交互，类似 ChatGPT 但与代码库深度集成 | 复杂任务、调试、解释代码 |

### 4.2 代码自动补全演示

以 VS Code + GitHub Copilot 为例：

**基础用法**：
1. 输入函数签名（如 `def download_contents(url: str) -> str:`）
2. AI 自动补全整个函数体
3. 按 `Tab` 接受建议

**通过注释引导**：
- 输入注释描述任务（如 `# extract all links from the given markdown document`）
- AI 根据上下文生成相关代码
- 可连续按 `Tab` 接受部分补全

**优势**：
- 节省打字时间
- 自动补全模板代码
- 保持手指在键盘上

**注意事项**：
- AI 是概率模型，可能生成看似正确但实际有问题的代码
- 使用前务必审查 AI 生成的代码
- AI 在简单任务上表现良好，复杂任务可能出错

### 4.3 内联聊天 (Inline Chat) 演示

选中一段代码，按 `Ctrl+I` / `Cmd+I` 打开内联聊天，输入指令：

```vim
# 示例：选中 import 语句
# 输入指令：
Don't use third party libraries.
```

AI 将基于选中内容和指令修改代码（红色为删除，绿色为新增），确认无误后接受修改。

### 4.4 编码代理

更高级的交互模式，支持：
- 对话式交流
- 询问 AI 解释代码逻辑
- 让 AI 提问以澄清需求
- 执行多步骤修改

按 `Ctrl+Shift+I` 打开编码代理窗口

> **注意**：当前 AI 模型本质上是"概率性下一个 token 预测器"，并非真正具有人类智能。使用时需要保持批判性思维，不能完全依赖 AI 的输出。

### 4.5 隐私问题

使用云端 AI 服务时，代码会被上传到服务器：
- 大多数工具提供隐私设置选项，可关闭数据保留
- 完全的隐私保护需要使用本地模型（如在本地运行的较小模型）
- 本地模型通常能力较弱，但可以完全控制数据流向

### 4.6 推荐工具

对于学生，推荐 **GitHub Copilot**：
- 通过 GitHub Education 注册可免费使用
- 需验证学生/教师身份

其他工具（如 Cursor，基于 VS Code）功能大致相当，可根据个人偏好选择。

### 4.7 使用策略

| 任务类型 | 建议 |
|----------|------|
| 简单重复代码 | 直接使用自动补全，让 AI 完成 |
| 复杂逻辑 | 描述清楚需求，或与编码代理对话 |
| 关键代码 | 务必审查 AI 输出，自行测试 |

**动态调整**：AI 工具能力不断提升，今天无法完成的任务可能在几个月后就能完美解决。保持使用习惯，了解工具的能力边界，及时更新认知。

## 6. 观众问答精选

### Q: 如何发现 Vim 的高级功能？

**A**:
1. 通过 Vim 教程系统学习基础命令
2. 使用中遇到繁琐操作时，主动搜索或询问 AI
3. 记住原则：如果某个操作很繁琐，一定存在更优解

### Q: 使用 AI 辅助编程是否需要联网？

**A**: 大多数情况下**需要联网**。当前主流 AI 模型（如 Copilot 使用的模型）是千亿参数级别的大模型，需要强大算力和 GPU 支持。本地运行的小模型能力较弱。

### Q: 何时用注释引导 AI vs 使用内联聊天？

**A**:
- 注释引导：适合在编写新函数时描述任务，让 AI 在光标处生成代码
- 内联聊天：适合修改已存在的代码（如重构、换掉第三方库）

### Q: AI 会消耗更多电量吗？

**A**: 是的，AI 推理需要大量计算，会显著增加电量消耗。

## 总结

本讲的核心要点：

1. **开发环境**：终端环境适合远程和轻量场景，图形化 IDE 适合需要丰富功能的场景
2. **Vim**：掌握模态编辑器的核心思想，学会组合使用移动、选择、编辑命令和计数/修饰符
3. **语言服务器**：通过 LSP 协议，IDE 可以获得代码补全、跳转定义、错误检查等智能功能
4. **AI 辅助**：自动补全可提高效率，内联聊天适合修改代码，但始终需要审查 AI 输出

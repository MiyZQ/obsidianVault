# 笔记库使用说明

这是一个以计算机技术学习和实践记录为主的 Obsidian 笔记库。根目录采用“主题文件夹 + Obsidian 配置 + 维护脚本”的组织方式：主题文件夹用于保存不同方向的笔记，`.obsidian` 用于保存当前库的 Obsidian 配置，根目录脚本用于 Git 初始化和日常同步。

## 根目录脚本

| 文件 | 用途 |
| --- | --- |
| `init.sh` | 首次初始化 Git 仓库、关联远程仓库并完成首次推送 |
| `Push.sh` | 日常生成快照并推送到 GitHub |

两个脚本都会自动切换到脚本所在目录，因此可以从其他位置调用。

## 首次初始化

在 Git Bash、Linux 或 macOS 终端中进入笔记库后运行：

```bash
./init.sh
```

脚本会初始化 Git、添加当前文件、创建初始提交、关联远程仓库 `https://github.com/MiyZQ/obsidianVault.git`，然后将当前分支推送到远程 `main`。

运行前请确认：

- 已安装 Git，并且终端可以使用 GitHub 的登录凭据。
- 当前目录确实是本笔记库根目录。
- 远程仓库地址是自己希望使用的仓库。

## 日常同步

编辑完笔记后，在笔记库根目录运行：

```bash
./Push.sh
```

脚本会执行以下操作：

1. 获取远程 `main` 分支的最新信息。
2. 将当前笔记库文件加入暂存区。
3. 根据当前时间生成快照提交。
4. 将快照推送到远程仓库。
5. 输出本地 Git 历史，方便确认同步结果。

如果内容没有变化，脚本会跳过提交和推送。

## Git 历史策略与注意事项

`Push.sh` 的设计目标是让本地和远程通常只保留最新的两条历史节点。当已有至少两条提交且内容发生变化时，脚本会重建提交历史，并使用 `--force-with-lease` 更新远程分支；同时会执行 `git reset --hard` 和 Git 对象清理。

因此：

- 该脚本适合个人笔记库，不适合多人共同维护的仓库。
- 它不会保留完整的长期提交历史，重要版本应另外备份。
- 推送前确认没有需要保留的旧版本或未备份改动。
- 脚本执行期间不要同时编辑、移动或大量重命名笔记。
- 如果推送失败或本地与远程状态不一致，先停止操作并检查：

```bash
git status
git log --oneline
git remote -v
```

如果希望保留完整 Git 历史，可以改用普通流程：

```bash
git add .
git commit -m "Snapshot: $(date '+%Y-%m-%d %H:%M:%S')"
git push origin main
```
